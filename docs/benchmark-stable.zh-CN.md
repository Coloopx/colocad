# 正式版 0.1.1 的三后端复测

[0.1.2 三后端连续改图复测](benchmark-revisions-0.1.2.md)

2026 年 11 月 17 日直接从公共 npm 下载包并核对完整性。机械与版本历史使用 Linux arm64 上的 Colocad 0.1.1、CadQuery 2.8.0 和 build123d 0.13.0。正式包包含已合并的 STEP 预算、圆锥曲线极值和相邻定义解析复用改动。[English](benchmark-stable.md) · [运行标识、原生文件哈希和依赖列表](benchmarks/stable-0.1.1/observations.json)。

## 连续保存 256 个真实几何版本

同一个导入的 KK60 滑台，修改相机板厚度、两孔间距。每轮先完成四个准备版本，再连续写入 256 个不同的装配，保存源、精确 STEP、预览与索引。三后端各用一个 vCPU、512 MiB、无交换、无网络和新建的 Linux 原生卷。先加载三套运行时，再按三个轮次轮换启动顺序。三轮各后端共 2,304 份改图 STEP、另有初次运行的 768 份，独立 OCCT 全部通过。

| 工作流 | 累计峰值 MiB（中位数，范围） | 第 128 版 MiB | 第 256 版 MiB | 后 128 版净增 MiB |
|---|---:|---:|---:|---:|
| Colocad 0.1.1 | **91.3** (91.0–91.4) | 68.3 | 74.3 | +6.5 |
| CadQuery 2.8.0 | **199.7** (199.6–200.3) | 195.5 | 195.9 | +0.8 |
| build123d 0.13.0 | **268.1** (261.2–272.1) | 258.4 | 264.4 | +6.0 |

峰值读取 Linux 的 `memory.peak`。当前占用读取提交返回后的 `memory.current`，取准备结束、第 1 版和之后每 4 版的样本。峰值列、当前占用列分别取三轮中位数。增长列先算每轮第 256 版减第 128 版，再取中位数。三轮范围反映了本机运行间的波动。256 次修改给出了该区间的实测增长，无法由此推断任意会话长度的渐近复杂度。

首次运行单列保留。三后端当时的峰值为 **82.9 / 259.0 / 300.2 MiB**。Linux 的共享文件页可计入首次加载它的 cgroup，这会改变容器中看到的绝对占用。原始数据同时保留文件页、匿名页和内核内存读数。[逐次采样、全部轮次与独立回读](benchmarks/stable-0.1.1/engineering.json)。

两个 Python 适配器使用 SQLite FULL 同步、文件 fsync 和干净页回收提示。Colocad 还保存原生检查点、查询快照和额外预览。Colocad 预览弦高为 1 mm，Python STL 的线性和角度参数为 0.15 mm 和 0.15 rad。独立验收以精确 STEP 为准，检查两个实体、安装孔、相机孔、窗口、材料、体积、接触与干涉，核对每版预览哈希，并恢复六个历史孔距。

## 建模、装配与交付

三后端各跑三次共 207 份 STEP，测量覆盖新进程启动、原生校验和导出。11 个产品用例各限 512 MiB，12 个规模点各限 2 GiB。按 Colocad / CadQuery / build123d 排列。

| 用例 | 到 STEP（秒） | 沙箱峰值（MiB） |
|---|---|---|
| 同一板件放置 128 次 | 0.60 / 1.69 / 2.30 | 51.7 / 260.8 / 301.7 |
| 64 种独立尺寸的板件 | 9.85 / 1.95 / 2.44 | 101.2 / 255.7 / 290.9 |
| 单实体 1,024 孔 | 45.44 / 3.94 / 3.67 | 311.4 / 240.8 / 275.4 |
| 43 实体灵巧手 | 2.12 / 1.73 / 2.10 | 51.0 / 207.6 / 244.8 |

一个 100 秒队列分别交付 **52 / 63 / 52** 份验收通过的灵巧手。约 25 ms 采样的沙箱峰值为 **200.4 / 512.0 / 291.3 MiB**。机械构建矩阵使用内核峰值，macOS 五产品实验使用进程树 RSS。三个指标各按原实验解释。[100 秒队列回读](benchmarks/stable-0.1.1/windows-verified.json) · [64 件独立板的分阶段耗时](benchmarks/stable-0.1.1/unique-phases.svg)。

## 外部 STEP 导入与资源上限

独立 OCCT 对照导入前后的实体数、体积、包络及有效性。19 个 STEP 中有 **17** 个通过；剩余用例为 mori, mushroom。同一源 STEP 的 32 个相邻定义只解析一次，命中 31 次，导出后回读到 32 个有效实体。输入 STEP、输出 STEP、报告三种字节上限均触发预期拒绝，输出目录无半成品。[逐件结果](benchmarks/stable-0.1.1/step-roundtrips.json)。

## 驻留 Pi agent 与 harness

| 任务 | 验收 | 沙箱峰值 MiB | OOM 终止 |
|---|---|---:|---:|
| 24 项原生语料及 Node 调度 | 通过 | 214.7 | 0 |
| Pi 四孔板改径与查询 | 通过 | 94.8 | 0 |
| Pi 82 实体执行器改行程与查询 | 未通过 | 333.9 | 0 |

每个任务使用独立的 1 vCPU、512 MiB、零交换 Linux cgroup。两条 Pi 任务在容器内运行 agent、harness 和 Colocad，推理在远端执行。表中保留各任务首次结果。[验收数据](benchmarks/stable-0.1.1/agent-sandbox.json)。

执行器首次改参已写出 STEP，模型在新版本上复查接口和间隙前结束了输出（结束原因为 `length`），因此判定失败。同一正式包、提示词、工具和验收标准，在新会话重试一次，结果为**未通过**，峰值 323.5 MiB。两轮最大的查询回执分别为 158 和 150 KiB，模型都以 `length` 结束。
