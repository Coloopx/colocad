# 实际建模操作、数据流与完整产品的验收

[完整方案：材料、工具、skill/提示词、调优](agent-modeling-handbook.zh-CN.md)在本次操作记录基础上给出可复用方法。

本说明区分已执行的操作与下一阶段拟采用的方法。熟悉某类机械的原理，有助于拆解设计；具体型号的尺寸、公差和内部结构仍需资料与测量支持。

## 当前实际执行了什么

本次实际完成的是 [HIWIN KK60 完整执行器复建](../examples/hiwin-kk60/README.md)，配置为 300 mm 导轨、5 mm 导程、单滑块、无选配电机与罩壳。此前的涡扇仍只是合成几何测试件。

| 阶段 | 实际输入与操作 | 实际输出 |
| --- | --- | --- |
| 查资料与读图 | 厂家目录 PDF；提取尺寸文字，渲染第 25 页，再放大检查剖视图 | 指定型号/配置，尺寸来源、坐标基准与假设清单 |
| 纠正读图 | 放大 SECTION A-A，把误读的 15 mm 丝杠中心高纠正为 23 mm | 更新共轴零件与接口尺寸 |
| 编写几何程序 | 助手依据图纸、数值和接口编写 `model.mjs` | 52 个特征及 81 个命名实例的生成器；运行时开放行程参数 |
| 实际执行 | 生成明确的 kernel JSON，调用 `ModelingSession.build` | 16 个阶段的源文件、回执、精确 STEP、预览网格 |
| 处理失败 | 总装触发内部 STEP 的 10 万实体限制 | 修复内部序列化预算、增加 Rust 回归；保留原失败会话 |
| 独立检查 | 用 OCCT 读回 STEP，检查实体、体积、孔/槽材料点与行程端点 | 可复现的验证脚本与 JSON 结果 |
| 人类查看与交付 | `colocad view / replay / render` | 本地查看器、单文件 HTML、四视图 MP4/GIF、整机 STEP |

**图像转参数化指令是本次助手读图与编程产生的中间结果，不是要求用户预先提供的输入，也不是 colocad 内置的自动图像转换能力。** 我先读取文字/图像并形成尺寸判断，再编写程序，colocad 执行明确指令。当前没有经过盲测的“任意图纸一键工业级复建”结论。

资料不足的内部结构仍标为假设：螺旋槽是有几何实体的近似，螺母回珠通道未还原，不能将验证通过解释为制造精度认证。动画也没有隐藏这些范围说明。

## 更适合真实产品任务的输入

先确定唯一的产品目标：厂家、型号、变型、行程或尺寸配置、版本。目标交付是该配置的完整产品，零件图和 BOM 是输入资料。优先取得总装尺寸、剖面、零件图、接口图和实物照片；若有参考 CAD，可单独留给验收使用。

输入不必全是图片。矢量 PDF 的尺寸文字、厂家参数表、图纸图像、剖视图和必要的局部裁图各有作用。图像提供视图对应和空间结构；准确数值优先取尺寸标注/表格；清晰度不足或互相矛盾的标注不能靠视觉印象补成精确值。照片通常用于核对形态，不作为未经标定的尺寸来源。

## 从本次操作整理的工作方法：尚非盲测通过的通用能力

1. **固定完整产品的规格。** 建立单位、坐标系、投影法、型号配置和验收范围，先确定总装包络、主要轴线、运动方向与安装接口。
2. **建立可追溯的尺寸记录。** 每个关键参数记录原文件、页码、标注区域、数值和单位。分清图纸给定、由关系推导、暂时假设、尚未知四种状态。关键未知项应体现在完成度中。
3. **先规划总装约束。** 建立零件定义、实例、父子关系、基准与配合接口。不要先随意画一批零件，再靠移动拼成看起来相似的产品。
4. **生成小步的建模程序。** 助手按工程含义选择旋转、拉伸、切除、扫掠、放样、阵列等操作，使用稳定 ID、命名尺寸和关系式。先实现安装与运动接口，再处理次要外观细节。重复件复用定义。
5. **执行并读取反馈。** 每个有意义的里程碑由 CLI/SDK 实际构建，保存输入和回执。失败后根据 feature ID 和几何反馈修改，保留失败记录。不能用略去关键结构来换取成功状态。
6. **定向检查，再接受版本。** 内核有效性、图纸尺寸、装配关系分别验证。生成与原图一致的投影视角/剖面检查轮廓和孔位；独立回读 STEP 检查实体、体积及内部区域。调整参数后复查受影响的接口和整机包络。

建议中间数据与内核输入分开保存：

```text
product.json       型号、配置、单位、坐标与整机验收要求
sources/           原始资料、页码与局部裁图
measurements.json  尺寸、来源、推导关系与未知项
interfaces.json    零件间接口、装配基准和运动关系
model.mjs          必要时使用的可编辑参数生成程序
model.json         给 colocad 的明确几何指令
history/           每次实际执行的输入、回执、STEP 和预览
```

其中前四项是建议的任务数据约定，当前不是 colocad 内核 schema 的新增字段，也还没有自动提取器。不能把这些任意字段塞入 kernel model。

## 给助手的有效任务约束

比“照图做一个工业级模型”更明确的提示应包含：

```text
目标：还原指定厂家、型号、配置的完整产品。
依据：列出图纸/手册文件及其版本，指定优先来源。
单位与基准：确认投影法、总装坐标、主要轴线。
精度目标：列出应核对的尺寸、公差、配合和行程。
未知项：不得默默替换为确定尺寸；单独记录假设与影响。
执行：先列整体布局和接口，再分阶段建模；保留失败与修改。
验收：给出整机、关键接口、内部结构的测量与对应视图。
交付：可编辑源、整机 STEP、建模会话、CLI 导出的离线回放。
```

不要只靠一个很长的提示。每轮仅给当前子系统所需的清晰视图、相关尺寸和接口约束，并保留共享整机基准。让校验返回具体数值与误差，而非只有“看着不对”。这套方法是否提高成功率，应通过实际任务记录证明。

## 如何判断效果真的提升

在相同型号、资料、模型版本和预算下，比较尺寸识别正确率、关键特征遗漏、独立几何检查、装配接口误差、未知项数量与人工修改次数。推理时间/费用、CAD 执行、预览分别计量。执行器更快，不直接等于读图更准；实体数更多也不等于完整产品更准确。

对于滚珠丝杠执行器，完整产品验收应覆盖所选配置的轨道/壳体、滑台、丝杠螺母、支承与连接，以及实际公开资料能确定的内部结构；还包括轴线关系、安装孔位、行程端点和旋转—平移关系。仅有外形 CAD 时，不能据此声称滚道、滚珠回流和制造公差均已还原。
