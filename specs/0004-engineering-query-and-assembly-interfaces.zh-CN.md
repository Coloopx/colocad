# SDD 0004 中文实施说明：工程查询与装配接口

**状态：修订提案第 2 版，正在分阶段实施和验收，尚未全量完成。日期：2026-11-09。**

**六项评审结论已纳入本版。** [CadQuery 对照评审](reviews/0004-cadquery-2026-11-09.md)的 F01 对应配合方向，F02 对应独立几何基准，F03 对应可组合选择，F04 对应拓扑/UV 类型，F05 对应接触间隙，F06 对应阶段与验收重排。实际实现和证据见[实验台账](experiments/0004/README.md)；按层冻结通过验收的 schema，不把规范本身当作完成证明。

[英文规范](0004-engineering-query-and-assembly-interfaces.md)是字段、错误码、阶段和验收编号的权威契约。本文解释实施意图和边界，不代表 alpha.6 已提供这些新 API。若两者不一致，以英文规范为准并修正文档。

## 1. 要解决的实际问题

当前 Colocad 可以按已知尺寸构建复杂零件，也可以用预先给定的坐标放置装配体。缺口是：面对陌生零件，不能统一查询安装面、孔、轴、孔组和接口，再把这些结果交给装配约束。

下一阶段必须接通：

```text
精确 B-rep
  → 可组合的拓扑选择与精确描述
  → 点/平面/轴线/坐标系等几何基准
  → 配合约束求解
  → 距离、接触与间隙验证

孔/孔组识别 → 可选安装接口 profile → 复用上述基准与配合
```

验收不是“能输出几个法向和孔径”，而是：**换一份兼容的电机或支架 STEP，同一工作流能够继续装配，不改面编号或零件定位坐标；不兼容、证据不足或方向有歧义时，明确报告。**

现有 `inspect()` 只是读报告；`inspect-step` 主要读取产品树与变换；mate 求解器主要消费调用者给定的 frame。KK60 案例证明了复杂建模和显式定位，不能据此宣称已经支持陌生零件的通用接口装配。

## 2. 能力放在哪一层

| 层 | 应承担的工作 |
| --- | --- |
| Rust 几何查询 | 拓扑遍历、解析曲面类型、法向/轴线/尺寸、精确材料判定、邻接关系 |
| Rust 工程识别 | 组合孔的圆柱片、孔组、安装面和接口；输出依据、覆盖范围及歧义 |
| 现有 mate/check 模块 | 消费接口 frame，求解约束并核对真实几何 |
| TS SDK / CLI | 类型、批量请求、文件和版本管理、预算、回执 |
| Agent / skill / workflow | 选择工程意图、给筛选条件、消除歧义、调用与验收 |
| Viewer | 高亮真实查询对象，显示面、孔、轴与接口依据 |

几何识别不应由每个 workflow 分别重写。领域标准可以做成版本化 profile；核心不能依赖某个电机型号、固定孔坐标或模型文件名。全部执行仍在现有沙箱内，不增加远程 CAD 服务。

## 3. 查询快照与引用：先解决“结果能不能再用”

建议通过 `client.build(model, {queryable: true})` 生成可查询版本，CLI 增加对应 `--queryable`。快照保存精确几何、拓扑 ID、名称绑定、零件定义、实例变换、来源和哈希。普通旧调用不强制付出查询快照成本。

不能直接复用现有增量缓存作为这个承诺：它是有预算的可选缓存，而且会跳过带拓扑名称的几何。M0 必须先证明精确几何与名称绑定能够保存、重启和回读；失败就不能开放稳定引用能力。

引用必须标明：

- 所属查询版本、零件定义及其摘要；
- 面或边的持久 ID；
- 必要时附上实例路径，区分同一个零件的两个实例。

同一份快照在进程重启、目录移动后仍须可用。改参、替换 STEP 或改变装配位姿后产生新查询版本，旧裸引用必须失效。语义接口通过重新解析声明取得新引用，不能靠“找最近的面”悄悄接上。

因此持久化模型的接口声明使用语义名称、几何条件和方向意图，不直接保存上一版本的 face ID 或候选 ID。查询引用用于原快照的观察与测量；新增 mate 后，声明在新版本重新校验，避免刚把查询结果写进模型就引用失效的循环。

面分裂、合并、删除可能让一个名称对应多个对象。必须返回明确的缺失/歧义状态；调用者要求单一安装面时不能自动取第一项。

## 4. 公开入口和返回内容

拟增加：

```ts
client.build(model, { queryable: true });
client.query(artifactDirectory, request);
```

```sh
colocad query REVISION_DIR REQUEST.json
colocad query REVISION_DIR REQUEST.json --out NEW_RESULT.json
```

Agent 层只增加一个可选批量工具 `cad_query`，不把每个面操作变成一个独立工具。一次请求最多 64 项独立查询，共享同一份已校验的快照。

声明 `datums` 或 `interfaces` 的模型自动启用查询快照；同时显式关闭 `queryable` 属于冲突输入。普通模型保持原开销。基准引用缺失/循环、方向歧义、退化和不支持的推导分别返回 `DATUM_REFERENCE`、`DATUM_AMBIGUOUS`、`DATUM_DEGENERATE`、`DATUM_UNSUPPORTED`；完整选择违反基数要求返回 `SELECTION_CARDINALITY`，不能静默取首项。

整体拟覆盖的操作包括 `faces`、`edges`、`describe`、`evaluate_face`、`holes`、`hole_groups`、`interfaces`，按下面的阶段逐步交付。[请求示例](examples/0004-query-request.json)中的摘要是示意值，实际执行必须换成构建返回的查询版本。

第 2 版按阶段交付：M1 增加 `vertices`、`loops`、`select`、`datums`，M2 增加显式双目标 `measure`，孔/孔组/工程接口在 M3 交付。capabilities 只能列出已实现并验证的操作，不能提前把整份提案都标成可用。SDK 的 `build(model, options)` 是新增重载，必须保留当前第二参数为 previousRevision 字符串的兼容性。

结果必须包含几何事实、引用、定义/装配坐标系、有效容差、来源、耗时、覆盖范围和候选歧义。完整回执保留在文件里，agent 只需读取当前相关信息。

`complete` 和 `partial` 有实际含义：无法识别某类曲面时，不能用空数组表达“没有孔”；分页也不能让调用者误以为候选唯一。批量请求失败时不能把前几项成功冒充整个请求成功。

## 5. 几何判定规则

**可组合选择：** 同一条有界表达式支持子拓扑、祖先/邻接、条件组合、集合运算、几何排序和基数检查；查询与持久声明共用语义。首期深度不超过 8、节点不超过 128。排序并列返回完整并列集合，不能用“取第一项”规避歧义。一批请求仍互不依赖，但一条选择表达式可在单次 native 调用完成“安装面 → 内边界环 → 圆边 → 圆心/方向”，不让 agent 在 TS 里重写几何逻辑。

**拓扑与 UV：** 引用包含 face、edge、vertex、loop，并有 describe/遍历入口。loop 保存有向 edge use；接缝可能重复使用同一 edge，不能去掉这种重复。面描述提供 native UV 域、周期与接缝信息；域内不等于裁剪面内。投影到原始曲面不等于落在真实裁剪面上。

**面法向：** 平面可以报告恒定法向，曲面必须在指定 UV 位置求值，并检查该点是否位于实际裁剪面内。面积质心可能落在孔里，不能直接当作面上的安装点。开放壳体不能凭空获得“朝外”的材料法向。

**圆柱与孔：** 圆柱面可能是轴、凸台或孔壁。孔识别必须结合材料方向、邻接关系、裁剪覆盖、入口与底部证据。半径相同且同轴，不足以把两个不连通的孔合并。

**首期孔识别范围：** 解析圆柱通孔、平底盲孔、同轴沉孔；需正确处理跨多个面片和周期接缝的同一个孔。交叉孔、侧开口、锥形钻尖、任意 NURBS 等价圆柱、螺纹等可以明确返回局部支持或不支持，不能错认成简单孔。

**孔组：** 在真实支承平面内识别线性、矩形、圆周或非规则组，报告成员、间距/PCD、残差和对称性。额外孔、多个合理子集都要保留，不按屏幕位置或世界包围盒推测。

**单位和容差：** 输出使用 mm、mm²、mm³、rad。几何比较容差、求解残差阈值和工程间隙要求分开；不能为了配合成功静默放宽。未知的原始精度仍然未知，数值查询通过不等于得到制造公差。

## 6. 安装接口如何声明与识别

**先交付独立几何基准。** 增加 `Model.datums`，声明所属 definition、选择表达式、推导规则、容差和输出类型：点、平面、轴线、方向、完整 frame。圆心可由圆边推导，轴线可由解析圆柱推导，方向可来自直边或两个命名几何点；不要求先识别孔组。

`Attachment.datum` 直接接入配合。无孔平面、轴承内孔、普通轴都能走这条基础路径。平面或轴线不是完整坐标系；内部为计算而补全的任意方向不能增加约束，也不能冒充已经确认的安装方向。框架的原点、正交性和手性必须显式验证。

自产模型优先声明，外部 STEP 再识别；两条路径输出相同的接口结构，但保留 `declared` / `recognized` 来源。

首期 profile 为 `planar_hole_mount/v1`：安装平面、孔组，以及可选的止口/定位轴。接口必须记录实际支承几何、原点规则、法向、轴线、尺寸、方向基准、来源和未约束自由度。

这个 profile 是 M3 的可选工程组合，不是基础装配的前提。安装方向优先引用从几何推导的 direction datum；数值向量必须标记为外部声明的意图，不能声称会自动跟随旋转后的新 STEP。来源变化后重新解析选择与几何关系。

[接口声明示例](examples/0004-interface-declaration.json)是拟新增 `Model.interfaces` 中的一项，不是可以直接交给 alpha.6 执行的完整模型。其中的零件 ID、拓扑名称和参数需要由建模源定义。声明也必须经过最终几何检查，不能代替实际孔和面。

接口原点可以位于孔组或中心孔的空心区域：它是支承平面上的基准点，不一定是材料接触点。需要分别记录裁剪面归属；只有声称“该点位于实际表面/接触区域”时，才要求它落在真实裁剪面内。

需要特别处理：

- 一个平面不能确定安装原点和面内转角；
- 一个平面加同轴定位通常仍有旋转自由度；
- 对称孔组可能允许多个离散方向；
- 方向未知时返回候选/自由度，或让调用者明确选择，不自动使用遍历顺序。

## 7. 如何接入现有装配

保留现有 `Attachment.frame`，新增与其互斥的 `Attachment.datum` 和 `Attachment.interface`。只有旧式附件可省略选择并使用旧默认 frame。几何先在零件定义坐标系解析，再经过嵌套实例变换进入装配坐标系。所需的基准缺失、过期、不支持或有歧义时，在求解前拒绝。

现有调用的默认语义保持不变，新增明确方向策略：concentric/revolute 可设 `alignment: aligned | opposed | unoriented`，默认 aligned。unoriented 在一次求解前根据初始姿态选择数值分支并固定，报告该分支，不能冒充确定了物理转角。

fixed/prismatic 可设 `alignment: aligned | opposed` 和 `twist_deg`（默认 0）。设 A 的轴为 X/Y/Z，s 为 aligned 时 +1、opposed 时 -1，θ 为绕 A 的 +Z 的转角，则目标 B 轴为 `X'=cosθ X+sinθ Y`、`Z'=s Z`、`Y'=Z'×X'`。这样反向安装仍是保持手性的旋转，不是镜像。fixed 重合原点，prismatic 保留沿 Z 的滑动。plane 原有 opposed 和有符号距离不变。

一侧固定时，点重合/平面关系/同轴/转动/滑动/固定分别通常保留 3/3/2/1/1/0 个自由度。CadQuery 的 Axis 不等于这里的同轴，Plane 也不能按名称直接映射。回执区分 mm/rad 物理残差与内部加权残差；不得悄悄固定自由运动。

**成功定位不等于尺寸兼容。** 拟增加显式 `interface_compatibility` 检查，验证安装面的关系、定位轴和孔对应关系，输出测量偏差。[兼容性检查示例](examples/0004-interface-check.json)给出孔轴偏差、面间隙和各自孔径范围；两个孔径不一样并不必然不兼容。

干涉/间隙还要检查实际 B-rep。允许接触的区域、指定零件对、姿态和阈值必须清楚；不默认对整机做所有零件对的布尔检查。所需检查失败时，记录失败尝试，不覆盖会话中已接受的源。

M2 的 `geometric_relationship` 检查明确 a/b 实例、可选语义区域、数值容差、最大重叠量、可选最小间隙和允许接触的区域对。输出 separated/touching/overlapping/contained/indeterminate、边界距离、所请求的重叠量和可提供的最近点/支承拓扑。边界距离不是穿透深度；完整包含不能因边界距离为正就判断无碰撞。区域算法不支持或证据不确定时不得降级为整对豁免或通过。

姿态采样首期最多 32 个/检查，并列出实际测试姿态。离散点通过不代表连续行程安全。旧 Collision/Opening/Containment 保持原含义；Opening 的最大距离不替代最小间隙。

## 8. 轻量化与性能约束

一次批量调用只加载需要的唯一定义，不按实例复制 B-rep。描述信息可用经过校验的索引；精确材料/配合结论依赖原始几何。缓存键包含版本、识别器、容差、目标、坐标系和筛选条件。

初始预算包括：64 项查询、256 个显式引用/项、256 条结果/页、2 MiB 请求、8 MiB 内联回执、64 MiB 精确快照。拓扑遍历、材料探针与模式假设另有明确计数上限，见英文规范 §8。查询不能突破现有外部 STEP 导入限制。

代表性用例必须在 Linux arm64 **1 vCPU / 512 MiB** 下验证完整 CLI/native 调用。分别测快照生成、加载、索引、识别、选择、求解和检查。基础描述查询不得偷偷重建、导出或三角化。

先建立实测基线，再决定更严格的延迟目标。与 CadQuery 对比时必须使用相同几何、精度、任务范围和输出，并区分冷启动与已加载几何。当前 spec 没有声称新的速度或内存优势。

## 9. PR 划分与验收

| 阶段 | 必须交付 |
| --- | --- |
| M0 | 核对固定内核能力，验证精确快照/名称/ID 回读，复现并修正方向冲突；只冻结通过验证的层 |
| M1 | 可组合选择/拓扑遍历、精确描述/求值、几何基准、快照引用和 SDK/CLI/tool；最小 STEP import→query |
| M2 | 基准直接驱动配合、方向适配、自由度/物理残差、显式测量与接触间隙 |
| M3 | 有边界的孔/孔组识别、可选工程接口、兼容性、零件替换与 KK60 指定姿态 |
| M4 | 查看器高亮、可运行示例、skill/文档、完整证据与发布 |

英文规范 §10 保留原有 20 项并增加 **S01–S02、D01–D04、C01–C02，共 28 项**。Q03 只检查裁剪域/接缝使用关系，识别同一个孔不重复计数移入 M3 的 Q06，消除 M1 对 M3 的隐含依赖。关键测试包括：

- 圆柱轴与孔不能混淆；沉孔分段尺寸正确；周期接缝不重复计孔；
- 旋转和嵌套实例后，局部不变、装配坐标正确；
- 修改版本、篡改文件、面分裂/合并/删除时，引用行为明确；
- 对称孔组、不完整分页、多个安装面时，不冒充唯一解；
- 更换兼容 STEP 可装配，不兼容孔距/止口必须失败；
- 运动配合保留应有自由度，冲突约束不能被隐藏；
- KK60 的指定接口与姿态完成真实配合检查；其他未测零件对明确说明。

每个阶段先写失败测试，再实现并回填证据。真实 STEP 用独立 OCCT 回读/测量核对；不能只让两个共享假设的程序互相证明正确。真实 agent 运行与脚本化 API 测试分别记账。

Q01 已固定为带通孔、平底盲孔和沉孔的 `100 × 60 × 12 mm` 板，明确孔位、分段尺寸及解析体积/面积答案。英文规范 §10 同时规定解析用例的数值误差阈值和外部 STEP 的精度记录要求，避免验收停留在“渲染看起来对”。
