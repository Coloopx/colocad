# SDD 0004 评审：以 CadQuery 为参照补齐工程查询与装配基础

**结论：Changes requested。方向成立，但当前版本不宜直接冻结 schema 或按原 M0–M4 顺序全面实现。**

后续状态：本评审结论针对 `1def0fb` 保留；六项要求已回归[英文第 2 版](../0004-engineering-query-and-assembly-interfaces.md)与[中文第 2 版](../0004-engineering-query-and-assembly-interfaces.zh-CN.md)。实现和验收进展见[实验台账](../experiments/0004/README.md)，设计问题已响应不代表所有实现验收已通过。

评审日期：2026-11-09。被评审版本：[Colocad `1def0fb`](https://github.com/Coloopx/colocad/tree/1def0fb)。对象为 [SDD 0004](../0004-engineering-query-and-assembly-interfaces.md)。本文件是评审与修订建议，不覆盖原规范，也不表示新增 API 已实现。

最重要的调整是：**先完成可组合选择、几何基准和基本配合，再把孔识别与安装接口做成上层能力。** 目前规范在快照、错误和引用上比较充分，但把“孔组安装接口”当成主要装配入口，通用几何查询到约束之间仍然缺了一层。另有一个已经通过现有 native 程序复现的方向契约冲突。

## 1. 证据和评审边界

阅读了 CadQuery 官方的 Concepts、Design Principles、Workplane、Selectors、Assemblies、Class Reference、Free Function API、Import/Export，并核对相关官方源码。

上游源码固定到 [`b3f9afd4f39cbd856d0c46aa30aa37b714b8f6cb`](https://github.com/CadQuery/cadquery/commit/b3f9afd4f39cbd856d0c46aa30aa37b714b8f6cb)。[来源清单及文件摘要](0004-cadquery/upstream-sources.json)记录了八个源码/文档文件。`/en/latest/` 是可变文档，不假定它与该提交完全一致，也不把文档出现的实验性能力视为某个已安装版本的保证。

本地核对了 Colocad 的 `mates.rs`、`operations.rs`、`naming.rs`、`assembly.rs`、`distance.rs` 和现有测试。运行了四个现有 native 配合探针；**未安装或执行 CadQuery runtime，未做性能对比，未执行尚未实现的 query API**。因此本文区分官方文档事实、源码事实、native 实测和设计推论。

## 2. CadQuery 提供的真正参照

| 层 | 核对到的 CadQuery 能力 | 对 Colocad 的意义 |
| --- | --- | --- |
| API 分层 | Fluent Workplane 与较低层 Shape/free functions 共存。[Concepts](https://cadquery.readthedocs.io/en/latest/primer.html#cadquery-api-layers) | Rust 几何、SDK、CLI/tool 应共用基础能力；业务 profile 不应成为唯一入口。 |
| 选择与遍历 | 逻辑组合、几何排序、拓扑 ancestors/siblings、不同拓扑类型之间的选择链。[Selectors](https://cadquery.readthedocs.io/en/latest/selectors.html) | “列出所有面再让 agent 算”不能替代一个可复用的选择层。 |
| 原始几何访问 | Face/Edge/Wire/Vertex、法向/曲线求值、几何量及 shape 距离等。[Class Reference](https://cadquery.readthedocs.io/en/latest/classreference.html) | 需要能供基准构造和测量直接消费的类型化查询。 |
| 装配消费 | `Assembly.constrain` 接收选择表达式、tag 或 Shape；基础约束不依赖安装孔组识别。[Assemblies](https://cadquery.readthedocs.io/en/latest/assy.html) | 应允许点、平面、轴线直接成为约束的输入。 |
| 设计意图 | 相对特征定位，避免把全部关系写成全局坐标。[Design Principles](https://cadquery.readthedocs.io/en/latest/designprinciples.html#principle-2-capture-design-intent) | 可重建的选择配方比一次查询得到的坐标更重要。 |
| tag 与 history | tag 引用 Workplane 状态；当前 Free Function API 还公开了实验性的操作 history。[Workplane](https://cadquery.readthedocs.io/en/latest/workplane.html)、[Free Function API](https://cadquery.readthedocs.io/en/latest/free-func.html) | 不能把 tag 等同于持久 face UUID，也不能再简单地说 CadQuery 只有 tag、没有操作历史。 |
| 外部模型 | 可以导入 STEP 后使用几何 API。[Import/Export](https://cadquery.readthedocs.io/en/latest/importexport.html#importing-step) | 最小外部零件查询用例应先于整机装配案例。 |

这些文档没有给出“任意 STEP 自动识别全部安装孔、恢复工程意图并自动装配”的保证。孔/孔组/接口识别是 Colocad 拟增加的工程层，不能用它替代更基础的选择与基准能力，也不能据此夸大 CadQuery 的现成能力。

### 不能直接照抄的行为

- CadQuery `Axis` 是方向角约束，并非直接保证两条轴线同轴；其 `Plane` 组合了 Point 与 Axis，不能和 Colocad 的 `plane` 按名称一一映射。依据是官方 [约束说明](https://cadquery.readthedocs.io/en/latest/assy.html#constraints)及固定版本的 [`ConstraintSpec.toPODs`](https://github.com/CadQuery/cadquery/blob/b3f9afd4f39cbd856d0c46aa30aa37b714b8f6cb/cadquery/occ_impl/solver.py#L243)。
- 对 Face 使用 Axis 时，源码取的是 `normalAt()`；圆柱面的局部法向不等于圆柱轴线。必须区分平面法向、圆边法向和圆柱轴线，不能把 `%CYLINDER` 后接 Axis 当作通用孔轴提取。[源码](https://github.com/CadQuery/cadquery/blob/b3f9afd4f39cbd856d0c46aa30aa37b714b8f6cb/cadquery/occ_impl/solver.py#L193)
- 上游装配查询最终调用 `res.val()`，并没有在这一层实现本 spec 要求的唯一候选检查。Colocad 应保留严格 cardinality，而非照搬取首项行为。[源码](https://github.com/CadQuery/cadquery/blob/b3f9afd4f39cbd856d0c46aa30aa37b714b8f6cb/cadquery/assembly.py#L317)
- 曲面中心处的求值、tag 和 experimental history 都不构成跨进程、跨修改的永久拓扑身份承诺。本 spec 的裁剪域、快照完整性、旧引用失效规则仍然有价值。

## 3. 必须处理的评审发现

### F01 · P1 — 朝外接口 frame 与现有同轴/固定配合不兼容

位置：[§7，接口 normal、frame 及保持旧 mate 语义](https://github.com/Coloopx/colocad/blob/1def0fb/specs/0004-engineering-query-and-assembly-interfaces.md#L221)。

规范要求两侧接口 +Z 都朝材料外，并要求复用现有 mate 语义。两个正确接触的安装面法向相反，而当前 `concentric` 的方向残差是 `b.z - a.z`，要求同向；`fixed` 也要求两侧 frame 各轴相同。把规范产生的两个 outward frame 直接传入这些约束，会拒绝正常安装姿态。

**实测：** 两个 `4 × 4 × 4 mm` 方块沿 Z 接触，共用安装中心，接触面 frame 分别朝 +Z/-Z。为隔离约束本身，前三项把两块都设为 anchor：

| 探针 | 结果 |
| --- | --- |
| `plane(opposed=true, distance=0)` | 成功，残差 0 |
| 上述 plane + `concentric`，使用同一对 frame | `MATE_INCONSISTENT`，同轴方向最大残差 2 |
| `fixed`，使用同一对 frame | `MATE_INCONSISTENT`，最大残差 20（旧实现的缩放值） |
| 只固定 A，使用 plane | 成功，保留 3 个自由度 |

这不是声称旧 `fixed` 本身实现错误，而是**新接口约定和旧求解器之间缺少明确适配规则**。对 plane + concentric，要求同时 `b.z = -a.z` 和 `b.z = a.z`，任何位姿都不能满足，并非初始姿态或局部求解收敛问题。

修订要求：分开定义材料外法向、无向几何轴线和配合方向；明确 `aligned/opposed/unoriented` 及有向 offset 的符号。接口到 solver frame 的修正旋转必须有契约，求解和兼容性检查必须使用同一解释。保持旧裸 frame 调用语义，新增适配不应静默改变旧模型。

同名/近似名称不能直接作为兼容表。下表是一个零件固定、另一个零件可动时的几何自由度分析；除上述 native 探针外，不是 CadQuery runtime 实测：

| 约束 | 实际关系 | 一般情况下剩余自由度 |
| --- | --- | --- |
| CadQuery `Axis`，角度 0°/180° | 方向对齐，不要求轴线位置重合 | 4 |
| Colocad `concentric` | 有向轴同向，且两轴线重合 | 2 |
| CadQuery 默认 `Plane` | Point 中心重合 + Axis 方向相反 | 1 |
| Colocad `plane` | 法向满足方向要求、法向距离满足要求，面内可滑动 | 3 |

这说明基础规范要写残差/方向/自由度，而不是简单列出“支持 Plane、Axis”。

新增验收：同向/反向轴表示同一物理轴线；反向安装面上的同轴配合；带显式转角的固定安装；方向冲突必须是真实冲突。

### F02 · P1 — 缺少不依赖孔组的几何基准装配入口

位置：[§6.3–7，唯一 profile 与 Attachment 形式](https://github.com/Coloopx/colocad/blob/1def0fb/specs/0004-engineering-query-and-assembly-interfaces.md#L203)。

新入口只有 `Attachment.interface`，首期 profile 强制安装面加孔组。普通轴装入轴承孔、两个无孔平面贴合、圆边中心对齐、点落在导向轴线上，都不应先构造法兰孔组才能装配。现有 frame 可以手写，但那会把中心/轴线提取和坐标拼装继续留在 workflow，正是这次用户反馈希望移走的工作。

建议增加独立的 `Datum` 层，至少表达 `point`、`plane`、`axis`、完整 `frame`，并保存其几何来源和选择配方。`Attachment` 可以引用这样的命名基准；孔组接口组合这些基准，而非替代它们。平面或轴的自由度不应因为适配器需要一个完整矩阵而被偷偷固定；计算用的任意补全轴也不得冒充已确定的工程方向。

新增验收：无孔平面对齐仍保留面内移动；轴孔配合保留滑动/转动；加轴向定位后保留转动；完整 frame 才支持全姿态锁定。约束的剩余自由度用明确几何关系定义，不按函数名猜测。

### F03 · P1 — 查询条件不足以保存可复用的相对选择和方向意图

位置：[§5.2 批量/where](https://github.com/Coloopx/colocad/blob/1def0fb/specs/0004-engineering-query-and-assembly-interfaces.md#L128)及 [§7 orientation_datums](https://github.com/Coloopx/colocad/blob/1def0fb/specs/0004-engineering-query-and-assembly-interfaces.md#L217)。

当前 where 是扁平过滤，既没有选中面到其边/环的遍历，也没有有界逻辑组合、几何排序/并列规则、相对已解析基准的方向选择。每批查询独立，无法在同一次 native 调用表达“先选安装面，再取它的内圆边，再取孔中心”。Agent 只能多次传输引用，或自己在 TS 中重建选择与解释逻辑。

持久方向声明也只允许 definition 坐标中的数值向量，不能表达“沿选中的定位边”“由两个定位孔中心确定方向”。因此重新旋转导入 STEP 后，旧向量并不会跟随其物理特征；要完成 A02，仍可能要求 agent 重写方向数据。规范没有定义这种重写何时算允许的材料适配，何时已经违反“不改定位坐标”的目标。

修订要求：定义有界、类型化的选择表达式，支持子拓扑遍历、关系谓词、逻辑组合与明确的排序/基数检查。Query 与持久声明共用该表达式的几何语义；快照 refs 仍仅用于观察。支持从已选几何构造方向与原点，并把补充人工方向意图和真正的几何推导分别标记。可以用单条有界嵌套表达式完成选择链，不必引入任意脚本或跨查询任务 DAG。

不要求复制 CadQuery 字符串语法，更不要求开放 `eval`。建议验证的概念链为：

```text
定义 → 按语义/几何条件选平面 → 内边界环 → 圆边 → 中心/法向
                                                   ↓
                                  命名基准 → 约束/检查
```

新增验收：安装面上圆边不会混入另一侧圆边；相同排序值不能任取首项；重新旋转输入后，基于定位边/孔的声明跟随几何；完全对称而无方向证据时仍返回歧义。

### F04 · P2 — descriptor 与后续查询之间存在未定义的数据类型

位置：[TopologyRef](https://github.com/Coloopx/colocad/blob/1def0fb/specs/0004-engineering-query-and-assembly-interfaces.md#L73)、[操作与 descriptor 表](https://github.com/Coloopx/colocad/blob/1def0fb/specs/0004-engineering-query-and-assembly-interfaces.md#L134)。

Face descriptor 要返回外/内 loop 引用，Edge descriptor 要返回 vertices，但 `TopologyRef.kind` 只有 face/edge，也没有 loop/vertex 的 describe/遍历契约。调用者得到这些结果后无法按已定义 API 继续访问。`evaluate_face` 要求 native UV，descriptor 却没有要求返回 UV 域、周期/接缝信息或点投影入口，agent 无法可靠地产生合法参数。

修订要求：要么定义 VertexRef/WireRef/LoopUse 及描述/遍历能力，要么把它们明确设计为可直接使用的有界内嵌值；不能保留没有消费者的“引用”。Loop 中的有向 edge use 与全局 edge 身份应分开，周期 seam 可能让同一 edge 在 face 上出现多次。添加求值所需的 UV 范围/周期、裁剪成员状态；投影到未裁剪底层曲面不等于投影到真实 face。

新增验收：环到边到顶点的闭合访问、共享边与重复 edge use、周期缝、环形面中心在孔内、退化点和无有效法向的状态。

### F05 · P2 — 接触与间隙验收仍缺可执行的检查契约

位置：[§7.1 的 exact interference/clearance 承诺](https://github.com/Coloopx/colocad/blob/1def0fb/specs/0004-engineering-query-and-assembly-interfaces.md#L266)。

规范要求 allowed contact regions、姿态采样和精确间隙，但新增 JSON 只定义了接口孔轴/面间距检查，没有定义接触区域怎么引用、最小间隙如何请求、最近点证据如何返回、相切/穿透/包含怎么区分、采样姿态与连续运动结论的边界。

现有 [AssemblyCheck](../../crates/agent-cad/src/assembly.rs) 是 Collision/Opening/Containment；已经有原生 [boundary_distance](../../crates/agent-cad/src/distance.rs)，不是缺少任何距离算法。但 `Opening.max_distance_mm` 不能直接替代“至少保留 0.2 mm 间隙”，整对零件允许碰撞也不能代替仅允许指定安装面接触。

修订要求：冻结一个有明确 pair/region、坐标系、阈值和结果状态的检查 schema。至少区分边界距离、实体重叠、包含、允许接触与无结论；说明是否返回可验证的最近点/支持拓扑。跨零件测量必须有显式双目标契约，不能违背普通 describe 的单 owner 约束后偷偷混用引用。超预算或数值不确定不得当作通过。

新增验收：刚好接触、0.2 mm 间隙、轻微穿透、一个实体完全包在另一个内；仅豁免安装面接触时，别处碰撞仍失败。离散行程点通过只能声称这些点通过，不能宣称全行程连续安全。

### F06 · P2 — 阶段依赖和基础验收需要重排

位置：[§10 验收矩阵、§11 M1/M2](https://github.com/Coloopx/colocad/blob/1def0fb/specs/0004-engineering-query-and-assembly-interfaces.md#L313)。

M1 引用了完整 Q03，而 Q03 包含“接缝不重复计孔”，这依赖 M2 的孔识别。现有矩阵也没有独立验收无孔平面、轴线基准、选择链，以及旧 frame/new datum 两种入口的数学等价性。照原划分交付，M1 可能已经完成较重快照体系，却还不能直接支撑最基本的装配调用。

修订要求：将 Q03 拆为求值/裁剪和孔识别两部分；让基础几何基准到 mate 的闭环先于完整孔组识别交付。M0 先验证关键内核操作与序列化，不应一次冻结尚待评审的全套接口 schema。各层独立冻结，保留已有资源限制和失败语义。

## 4. 建议的修订顺序

以下是评审建议，尚未成为替换版规范。

| 阶段 | 可独立验证的交付 | 必须先过的用例 |
| --- | --- | --- |
| M0 | 固定内核能力清单；方向/单位/容差/DoF 契约；精确快照与名称回读探针 | F01 反向法向反例；序列化/重启；支持/不支持清单 |
| M1 | 有界选择与遍历、descriptor/evaluation、命名 Datum、可查询快照；SDK/CLI/tool 共用契约 | 外部 STEP 的最小 import→query；环/边/点；相对选择；旧引用失效 |
| M2 | Datum 直接驱动现有求解器；明确 mate 方向适配；基本测量/接触检查 | 无孔平面、轴孔、点/轴/面约束、自由度、反向法向、真实冲突 |
| M3 | 有边界的孔/孔组识别、声明与识别接口、兼容性、可替换零件 | 电机/支架替换、额外孔/对称性、独立 STEP、KK60 指定接口与姿态 |
| M4 | 查看器高亮、完整回执、文档/skill、资源与回归证据 | 原有 API 回归；完整案例；明示覆盖范围后发布 |

选择表达式、基准和 profile 都由 Rust 实现几何含义，TS 提供类型与易用构造器；CLI 与 `cad_query` 共用同一路径。全部仍在 agent/harness 所在沙箱内执行，不新增远程 CAD 服务。

先补一个低复杂度但完整的基线：**导入无命名的轴与支承座 STEP → 查询并声明几何基准 → 定位/保留自由度 → 验证距离与干涉 → 改尺寸或旋转输入再执行**。然后再做法兰孔组和 KK60，避免复杂产品掩盖基础 API 缺口。

## 5. 必须保留的设计

- 精确 B-rep 是权威，显示网格不是几何证明。
- 本地批量调用、唯一定义复用和资源上限；不为每个面创建工具，也不增加远程 worker。
- 持久观察快照与可重建语义声明分开；参数变更后重新解析，不自动寻找最近面。
- cardinality、partial coverage、对称性和未知精度明确；不能用“成功返回一个对象”代替确定性。
- 几何比较、求解阈值和工程公差分开；安装成功不等于兼容或无干涉。
- 无关旧调用不强制付出新查询成本；性能分阶段测量，不预先承诺倍率。

缓存可在不可变 definition digest 下复用几何索引，实例位姿变化只重算依赖位姿的结果；公共 occurrence 引用仍严格验证 assembly revision。是否采用这一分层应由 M0/M1 测量确认，不能因更严格身份校验反复加载未改变的定义。

## 6. 复现与结案要求

在仓库根目录运行（替换为当前平台 native 路径）：

```sh
python3 specs/reviews/0004-cadquery/probe-mates.py \
```
