# SDD 0006：受限沙箱中的有界工作集与持久化

日期：2026-11-11。目标版本：**0.1.0-alpha.9（计划）**。本规格不代表版本已发布或生产迁移已完成。

立项：[issue #1](https://github.com/Coloopx/colocad/issues/1) · [alpha.9 milestone](https://github.com/Coloopx/colocad/milestone/1)。M0 已完成，见[量化报告](../docs/memory-persistence-report.zh-CN.md)；开发分支已将 M1 的 Rust 索引、旧账本迁移和分页接到 SDK 与 CLI。[M1 验收](../benchmarks/session-catalog/README.md) · [使用说明](../docs/indexed-sessions.zh-CN.md)。几何落盘、流式 STEP、查看器分页和发布属于 M2–M5。[English](0006-bounded-memory-persistence.md)。

## 问题与目标

现有 agent、harness、SDK 和 Rust 执行器都在同一沙箱内。用户报告 Python CAD 在大零件/多零件过程中越过 2 GiB；本次三后端实验检验该现象，同时检验 Colocad 自身。旧版本的 128 特征/实例和 1024 切孔拒绝边界不是大模型扩展性证明。

目标是让**驻留工作集由显式字节预算决定**，而不是随已经完成的零件数或历史长度增长。历史/对象索引支持 O(log N) 查找，采用有界页缓存；不承诺完整精确模型、输出文件或全部曲面同时驻留时只有 O(log N) 空间。

定义 N 为实例数、D 为独立定义数、H 为历史事件数、Gᵢ 为定义 i 的精确几何大小、W 为当前依赖前沿。目标峰值为：

`M_agent+harness + M_runtime + M_active_geometry(W) + M_operation_temporaries + B_index + B_io + M_charged_file_cache`。

对不可进一步共享或压缩的一般记录，磁盘下界为 Ω(ΣGᵢ + N + H)；读取或导出全部几何至少要处理对应总字节。单个布尔/圆角的最小工作集若超过预算，应在可预测时拒绝并给出诊断；分块装配不能解决任意单实体的大型全局几何运算。

## alpha.8 基线与风险

- Rust 按最后使用次数转移/释放中间 B-rep；共享实例复用定义。`peak_live_feature_bodies` 只是对象计数，不能证明内核 arena、分配器或 RSS 已回收。
- 装配仍累积全部最终定义和交换表示；STEP writer 累积记录字符串再生成整份文本；查询快照与返回产物也集中在内存中。
- 增量 checkpoint 的 12 MiB、查询几何的 64 MiB 是局部缓冲限制，不是整个进程的内存上限。
- `ModelingSession` 每次读取/重写完整 `session.json`：单次 O(H) 内存/IO，连续追加累计 O(H²) 元数据 IO。回放打包还会同时持有不同版本的网格、PNG、STEP 和 JSON 字符串。
- SDK 输入仍为整体 JSON；仅改 native 不会消除宿主输入、历史和 HTML 打包的内存峰值。

## 设计决策

1. **项目目录与事务目录。** 采用版本化 catalog、内容寻址几何/网格/源文件和追加事件。Python/SQLite 只用于本次实验原型；产品实现位于本地 Rust 包，TS SDK/CLI 不新增 Python 运行依赖，也不引入远程 worker。
2. **持久索引。** 对对象、版本、事件和装配位置建立磁盘索引，使用固定字节页缓存。只分页返回事件/实例；`latestGeometry` 通过已提交 head 查询。禁止再把全项目清单读成一个 JS 数组。
3. **提交协议。** 先写临时文件、流式计算 hash、fsync，再原子发布并提交 catalog。崩溃前未提交的对象不成为 accepted head；恢复和 orphan 回收保留失败记录。路径、hash、版本和现有 stale-ref 规则继续生效。
4. **执行前沿。** 编译依赖图为分页计划，按字节估算/实测租用几何预算；最后使用后释放或落盘。对共享定义去重。验证内核实际释放行为；必要时使用当前沙箱内的有界本地子进程结束来回收内存，不以远程服务搬走账单。
5. **产物流。** 将 `BTreeMap<String, Vec<u8>>` 改为带临时目录的 artifact sink；逐定义写查询快照、网格和 STEP 记录，hash 使用固定缓冲。改写发生前先保留 alpha.8 输出兼容测试。
6. **两种导出契约。** 分块项目应完整保留几何、装配位置、源参数和查询入口；单个装配 STEP 需要单独实现/验收流式实体编号、引用、产品层级与独立回读。分块 STEP 集合不能冒充已经完成单文件导出。
7. **按需查看。** `colocad view` 分页加载历史与可见定义，限制网格预算。单文件 embedded HTML 保留为显式导出，提供估算和大小/内存拒绝；浏览器最终加载整份 HTML 仍有 O(展示数据) 下界。
8. **预算与诊断。** 配置 total CAD budget、active geometry、index、IO buffer、preview budget，并给 agent/harness 留出空间。错误包含触发阶段、已知量/估算量、可恢复位置和建议拆分粒度。禁止默默降精度或吞掉特征。

大项目协议需另行版本化：当前 SDK 的整份模型 JSON、完整 artifact hash map、2 MiB 回执限制都不能直接放大。新入口分页接收定义/实例，回执返回项目 revision、索引位置、摘要及游标；旧入口保持既有范围和结构化限制。不得只移除 128 上限而留下这些全量结构。特征中间态优先持久化精确 native snapshot；不能用 STEP 回导绕过拓扑/引用契约。低内存查询至少需要能装下所选定义，任意单定义超预算仍是明确限制。

实验同时分离整个装配的有效性验证、体积计算、实体枚举与导出。若局部定义和刚体位姿的组合证明能替代某项全局重复验证，必须保留独立几何回读与数量/孔/接口验收；不能为通过资源预算直接删掉正确性检查。

## 实施阶段与验收

| 阶段 | 交付 | 必须通过 |
| --- | --- | --- |
| M0 | 冻结三后端基线、极限测试、分块/索引原型 | 保留成功、OOM、超时和限制拒绝；同几何；公开环境、原始时序和独立回读 |
| M1 | Rust catalog + SDK 会话迁移与分页 | 真实 10k 次追加；100k/500k 元数据诊断另列；头查询不整本加载；断电/kill/事务恢复/旧版本迁移；查询引用不失真 |
| M2 | 字节预算、artifact sink、定义落盘与按需回读 | 当前 G1–G3 与 alpha.8 孔阵列回归全绿；相同精确交付；分配器/子进程与 cgroup 实测；错误可恢复 |
| M3 | 大装配与单 STEP 流式导出 | 超过旧 128 实例边界的独立定义和共享实例；位姿/BOM/实体/体积/孔与关键接口独立回读；不得仅提升计数上限 |
| M4 | 查看器分页与 HTML 预算 | 长历史首次打开/定位/回放保持预算；缓存有界；导出超限有结构化诊断；已接受历史无丢失 |
| M5 | 配对验收与发布 | 原生 arm64/x64；同架构、相同精度/交付；重跑冻结基线与 holdout；文档/skill/npm/native 一起发布 |

候选资源目标（须在正式验收前冻结）是：CAD 子系统 512 MiB，在包含 agent/harness 的 2 GiB 沙箱中另测整体；索引缓存 8 MiB、IO 缓冲 8 MiB 起步。对固定复杂度的分块项目，N 从 128 增至 2048 时匿名峰值增幅 ≤15%；历史 H 从 10k 增至 500k 时 head 查询额外匿名内存 ≤16 MiB。阈值只用于目标范围，不能掩盖磁盘、延迟或单实体限制。

单 STEP 兼容性、真实追加吞吐、随机定义回读、引用稳定性、失败恢复和视觉回放都必须验收后才能声称 alpha.9 完成。原型内存平台期本身不足以通过 M1–M5。

## 与 G4/RSI 的关系

本项目是 G4 的一个受限开发实验，不等于整个自动优化执行器已交付。每项优化保留一个可复现假设，固定验证器和几何，先检查正确性、资源及拒绝行为，再比较耗时、IO 和磁盘。常用样例属于开发集；不可继续叫未见测试。发布需要维护动作，不由 benchmark 得分自动触发。
