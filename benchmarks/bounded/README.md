# Matched alpha.9 experiments

Use the same frozen workloads, memory monitor and OCCT verifier in `benchmarks/memory` and `benchmarks/session-catalog`. The comparison is between Colocad revisions; there is no new Python-backend speed claim here.

1. Install or unpack the public `@coloopx/colocad@0.1.0-alpha.9` into a separate directory. Use the Linux arm64 memory benchmark image described in [the memory experiments](../memory/README.md). For the candidate, run `npm run build:kernel` for the host. For Linux, run the pinned [Dockerfile](../../scripts/Dockerfile.native) with a minimal context containing the checkout's `Cargo.toml`, `Cargo.lock`, `crates/` and `third_party/` (including the verified source archive and patch); use Buildx `--platform linux/arm64 --output type=local,dest=LINUX`. Test the named files in that output. Building solely against the upstream archive misses the candidate's Level‑1 change.
2. `python3 benchmarks/bounded/compare.py RUNS --baseline-package OLD --candidate-binary LINUX/agent-cad --repeats 3` runs the 12 existing geometry inputs, both variants, fresh 1 vCPU / 512 MiB / no-swap cgroups. It alternates order across repeats and saves input hashes, complete receipts, traces and one STEP per digest. Deduplication happens **after** the monitor exits. Take the median of the three fresh runs, not the fastest. Reuse an output directory only to resume exactly the same input and executables.
3. Run `python3 benchmarks/bounded/session.py OLD OLD_OUT OLD_DATA` and `python3 benchmarks/bounded/session.py . NEW_OUT NEW_DATA --kernel LINUX/agent-cad --catalog LINUX/colocad-catalog` on the same filesystem. Each output/data directory must be new. The timed workload executes every query, verifies all edits and pages back all 10,001 ordered entries. Then use `node benchmarks/bounded/audit-session.mjs DATA/edits` on each closed project with the candidate SDK. This extra audit checks all full receipts, query requests, revision bindings and 101 STEP file hashes outside timing.
4. Independent geometric acceptance: `python3 benchmarks/bounded/geometry-audit.py RUNS` compares both variants on every trial and runs the original OCCT verifier once per distinct artifact in the same pinned image. It rejects mismatched STEP bytes as well as invalid measurements.
5. To isolate Level‑1 from volume and bounds on macOS, create a **separate** checkout of `v0.1.0-alpha.9`; apply [the phase timers](alpha9-phase-timers.patch) there before building its host executable. This patch only adds timers. Run `python3 benchmarks/bounded/level1.py OLD_PROBE CANDIDATE RUNS/part-1024-before-0/input.json LEVEL1.json`. Compare the direct timer only within a platform; use Linux production binaries for end-to-end results.

The [standalone report](../../docs/benchmarks/bounded/comparison.html) embeds the measured rows, validation and methodology. Absolute peaks include monitor, descendants, filesystem cache and kernel metadata; peaks sampled in different accounting categories are not additive.

The isolated timer and Linux medians come from separate experiments. A fresh process does not imply a cold host filesystem. The session memory chart uses periodic `memory.current` samples; its headline uses the kernel high-water mark. Milestones, when available, align the workload's printed UTC timestamps to the trace file creation time and are approximate.
